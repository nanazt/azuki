# 재방문 로그인 유지와 전체 로그아웃의 범위

현재 azuki는 24시간 유효한 JWT와 쿠키를 발급하고 자동으로 갱신하지 않아요.
기존 로그아웃은 사용자별 `token_version`을 증가시켜 계정 전체의 JWT를 무효화하는 구조지만, 이미 열린 WebSocket은 인증을 재검증하지 않아요.

로그인 유지(Login persistence)는 이용 중 만료 방지에 한정하지 않고, 브라우저를 닫거나 기기를 껐다가 며칠 뒤 재방문해도 Discord 로그인 절차 없이 이용하는 범위로 결정했어요.
따라서 현재 24시간 JWT가 유효할 때만 재발급하는 방식만으로는 선택한 이용 범위를 충족하지 못해요.

로그아웃은 현재 브라우저만 종료하는 방식으로 바꾸지 않고, 같은 계정의 모든 브라우저와 기기에 적용되는 전체 로그아웃(Global logout)의 의미를 유지하기로 했어요.
이미 열린 WebSocket에도 같은 종료 의미를 적용하는 방향이에요.

미접속 만료(Inactivity expiration)는 해당 브라우저의 로그인에서 이용으로 인정되는 접속이 없는 기간이 7일에 도달할 때 적용하기로 했어요.
최대 로그인 유지 기간(Absolute session lifetime)은 최초 Discord 로그인부터 90일로 정했어요.
계속 이용해도 90일 상한은 연장하지 않으며, 두 만료 조건 중 먼저 도달한 조건에 따라 다시 로그인해요.

이용 중인 대시보드(Active dashboard)를 기준으로 미접속 기간을 갱신해요.
화면에 표시된 탭에서는 클릭이나 키 입력 없이도 갱신하지만, 숨겨진 탭의 자동 통신이나 WebSocket 이벤트 수신만으로는 갱신하지 않기로 했어요.
숨겨진 탭을 실제 이용으로 간주해서 미접속 만료가 계속 밀리는 동작을 제외하는 선택이에요.

새 방식을 배포할 때 기존 로그인은 종료하고, 사용자가 한 번 다시 Discord 로그인을 거쳐 새 정책으로 시작하기로 했어요.
유효한 기존 JWT를 새 방식으로 자동 전환하는 대안 대신, 일회성 재로그인 불편을 수용하고 임시 호환 경로를 두지 않는 전환을 선택했어요.

현재 코드에 근거한 자격 증명 구조의 기술적 권장안은 [기존 JWT 구조 유지](0002-retain-jwt-for-renewable-login.md)에 별도로 기록했어요.
사용자가 선택한 동작 정책과 기술적 권장안을 구분해요.
이 기록은 인터뷰에서 정한 동작 범위이며, 구현이나 배포를 승인한 기록은 아니에요.
